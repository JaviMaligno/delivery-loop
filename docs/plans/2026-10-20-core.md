# delivery-loop core — implementation plan (PR 1)

Spec: `docs/specs/2026-10-20-delivery-loop-design.md`. Real org profiles live in private repos (spec §9), outside this plan.

goal: public core plugin — skills `deliver`, `census`, `spec`, `qa-design`, `qa-execution`; profile schema+defaults; deterministic profile merge script; agnostic check; examples; CI.
style (spec §11): skills/profiles in terse technical English. No prose explanations; reason only if it changes application (≤1 line).
stack: Markdown skills; Python 3 stdlib (`unittest`); GitHub Actions.
workspace: worktree `../delivery-loop-wt-core`, branch `feat/core` from `origin/main`. Commit per task. PR → main; merge after audit.
local verification: `python -m unittest discover -s tests` + `python scripts/check_agnostic.py` + `claude plugin validate .` (validate is local-only: CI has no claude CLI).

## Decisions made in planning
- D-P1 profile merge = script `scripts/merge_profiles.py`; deterministic, testable. Skills call it.
- D-P2 grammar (machine-parsed; English keywords in any language). Pinned in `profile/schema.md`:
  - `## <section>` (lowercased). Unknown sections allowed (e.g. `transversal`).
  - field: `- key: value` — split on first `": "`; key kebab-case; one line; `[invariant]` suffix locks it. Duplicate key in one file → error. Capability absent: `- kind: none`.
  - lists: one key per item (`dev: <url> · branch <b>`), never multi-line.
  - `Rules:` line → rules `- [id] text` | `- [invariant id] text`; id kebab-case, scope = section; duplicate id in one file → error; bullet without id → error.
  - `Source: <text>` per section; nearest wins.
  - text outside bullets ignored.
- D-P2b levels far→near: L0 `<plugin>/profile/defaults.md` (script loads it, `--defaults` overrides path); user `~/.claude/delivery/profile.md`; each ancestor `.delivery/profile.md` from filesystem root to cwd.
  - paths resolved; dedupe by `os.path.normcase`.
  - `~/.delivery/profile.md` → error "use ~/.claude/delivery/profile.md".
  - above cwd's git toplevel, skip ancestors that are git work-tree roots (`.git` dir or file) → nested worktree doesn't collect the main checkout's profile.
  - merge: fields nearest wins unless locked; rules by id nearest wins unless upper invariant; restating invariant with identical text = no conflict; conflicts reported, exit 0.
  - CLI exit: 0 ok; 1 malformed (file:line); 3 = no profile beyond L0 found (still renders) → census trigger.
- D-P3 agnostic check: public `scripts/agnostic-denylist.txt` = tool names + fictitious `acme-corp` for fixtures; company/client names only via `--denylist PATH` (repeatable, private repos supply). Scans `skills/`, `profile/`, `scripts/`, `README.md` (`examples/`, `docs/`, `tests/` exempt; the denylist file itself exempt). Line containing `agnostic-ok` exempt (schema examples column). Case-insensitive word boundary.
- D-P4 phase files loaded per phase via Read; script path = `<skill base dir>/../../scripts/merge_profiles.py`; interpreter: `python` → `py -3` → `python3`.
- D-P5 delegation by capability ("session has a TDD/debugging/brainstorming skill → may use it"), never skill names.
- D-P6 opinionated methodology rules (never stash, explicit add paths, copy untracked env files, re-review after fixes, census staleness 30 d) = id'd non-invariant rules/fields in `profile/defaults.md`, overridable. Spec rules (§2.4 code-read ≠ measured, precedence source>spec>plan>code, read real code before plan) go in phase files + transversal.
- D-P7 task file `.delivery/tasks/<slug>.md` (phase 0): size+reason, mini-inventory if trivial, D0.x, escalations. Answer routing: durable → profile, else task file. Census adds `.delivery/tasks/` to repo `.gitignore` unless profile `vcs.commit-task-file: yes`.
